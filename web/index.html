Custom Field Boosts

How much a match in each field counts — a higher number floats matches in that field to the top. Applies to the boosted recipes (Boosted by name, Cross fields, Typo-tolerant, As-you-type) in both the playground and live scoring; the equal-weight recipes ignore them and “Default site search” always searches every field. Index-side settings (analyzers, synonyms) need an admin rebuild and aren’t adjustable here.

Which column types can be boosted?

Only free-text columns are eligible match targets: STRING, STRING_LIST, LARGETEXT, MEDIUMTEXT. Everything else — ENTITYID, DATE, INTEGER, DOUBLE, BOOLEAN, FILEHANDLEID, USERID, and their *_LIST variants — isn’t text to match against, so it's left out automatically. This only applies to auto-discovered indexes; curated tables ship a hand-picked field list.

Committed runs come from benchmark/run.py; the golden sets are benchmark/<index>/golden.yaml. Live queries in the lab hit the public Synapse repo-prod search API anonymously and reflect each index’s current production config.
