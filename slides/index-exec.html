Setting we control, 1 of 3 · how the search reads text

How the text is read decides what can be found

Before anything can be searched, text has to be broken into findable pieces. We choose that rule for each part of a record — and the choice can be the difference between every right answer and none.

ONE SEARCH — “hybridoma cell line”, the cells used to make antibodies — UNDER TWO READING RULES
Read as an exact label
0 results
It has to be typed perfectly, capital letters and all. The catalogue says “Hybridoma”, people type lowercase, and nothing matches at all.
Read as ordinary text
all 3 found
Lowercased, trimmed back to word stems, our NF vocabulary applied. Same records, same search — now every right answer comes back.
Why this
matters to you

Same catalogue data, opposite outcomes — the only difference is the reading rule. Reading rules can be set on each indexed attribute. It is powerful in both directions, which is why nothing changes without being benchmarked first.

The settings running on the studies catalogue today

What the weights buy

The old behaviour gave every part of a record an equal vote. So a study that merely mentions “therapy” in its summary can outrank one whose tumour type actually is schwannoma.

Only 3 of the 17 parts of a record are searched at all, and that is deliberate. Searching NTAP returns 101 studies; ntap returns zero. People type in lowercase, so those parts could never help — and taking them out made the results better.

Remaining gaps · 5 of 48 searches

What are still refinements

5 of the 48 searches in the research tools answer key still fail outright. They fail for three different reasons.

Continued search tuning

Everyday words drown out specific ones

Search weights can still weigh common words more against rare rare ones: "cell line" is on hundreds of records, "melanoma" on handful, but common words currently win. Still a search configuration to address.
