# nf-tools golden set — dataset documentation

Companion notes for [`golden.yaml`](golden.yaml), the relevance ground truth for the
**nf-tools** SearchIndex (`syn75081636`, source table `syn51730943`). Per-field semantics
and the case schema are documented in the header comment of `golden.yaml` itself; strategy
results are in [`RESULTS.md`](RESULTS.md). This file records dataset-level provenance and
**coverage gaps** — queries we deliberately did not turn into cases, and why.

## Coverage gaps — eval questions considered but NOT adapted

From the nf-osi/kg-pipeline eval (`eval_tools_ground_auto.yaml`, reviewed 2026-06-22).
These are nf-tools-relevant intents we could **not** turn into a golden case — recorded so
the gap is visible and not silently re-attempted.

**Out of scope (different index):** all Studies `ST-*` questions target **nf-studies**, not
nf-tools, and are omitted entirely.

**Dropped as redundant** with an existing case: `AM-001`→`optic-glioma`,
`AM-003`→`minipig-model`, `CL-001`→`plexiform-neurofibroma`, `GR-001`→`crispr-plasmid`,
`MUT-002`→`nf1-flox`.

The rest could not be grounded, by category:

### A. Attribute not in the nf-tools schema (would need a new source column)

| Eval | Question | Why not |
| --- | --- | --- |
| CL-005 | human cell lines from pediatric donors | `age` is uncategorized free-text numerics (no units/age-band), so "pediatric" can't be bounded reliably. |
| CL-007 | MPNST cell lines with population doubling times under 48 hours | No doubling-time column. |
| GR-003 | vectors with a CMV promoter | No promoter column. |
| GR-005 | vectors with resistance markers suitable for mammalian selection | No selection-marker column. |

### B. Relational / cross-record (a single-column filter can't express the link)

| Eval | Question | Why not |
| --- | --- | --- |
| AM-005 | transplantation models (xenografts) **and related donor cell lines** | The xenografts ≈ the `pdx` case, but the model→donor-line linkage isn't modeled. |
| CL-008 | isogenic cell line pairs differing only in NF1 status | No isogenic-pair flag. |
| CL-009 | cell lines from different tissues of the same donor | No donor-grouping key. |
| CR-002 | human cell lines with the most diverse data types on the portal | Portal-level metadata, not a property of the tools table. |
| CR-003 | animal models and cell lines derived from the same donor | Cross-type donor link. |

### C. Mutation-level — belongs to the nf-mutations index (`syn75081643`)

nf-tools has no per-variant column. `MUT-001` (ClinVar `NM_000267.3(NF1):c.2041C>T`),
`MUT-003` (`c.104del`), `MUT-004` (splice-site variants), `MUT-005` (cell lines with
mutations in multiple genes), `MUT-006` (mutations shared between animal models and cell
lines).

### D. Investigator / funder lookups (metadata too sparse, or not a retrieval)

| Eval | Question | Why not |
| --- | --- | --- |
| PI-001 | tools developed by Piotr Topilko | `investigatorName` is ~5% filled and this PI isn't present; not groundable (and a sparse known-item lookup, low benchmark value). |
| PI-002 | how many tools funded by GFF? | A count, not a result set; no funder column. |

> [!NOTE]
> Several of these (group A especially) are **metadata gaps, not search bugs** — they'd be
> answerable if the source registry annotated the attribute. Compare `cafe-au-lait-spots`
> in `golden.yaml`, which *was* kept: the manifestation is missing on the animal models, so
> it surfaces as a genuine recall gap rather than being dropped.
