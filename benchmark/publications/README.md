# nf-publications golden set — dataset documentation

Companion notes for [`golden.yaml`](golden.yaml), the relevance ground truth for the
**nf-publications** SearchIndex (`syn75081631`, source table `syn16857542`, 260 rows) — the
**publication-grained** index (one row per publication). Per-field semantics and the case schema
are in the header of `golden.yaml`; how cases are produced is in the
[`generate-goldens`](../../.claude/skills/generate-goldens/SKILL.md) skill. This file records
dataset-level provenance and **coverage gaps** — queries deliberately not turned into cases, and
why.

> **Not** the same as `nf-publications-v2` (`syn75081644`), a *usage-grained* table (1892 rows,
> ~655 distinct publications, one row per publication×resource). That set lives locally at
> `benchmark/usage-publications/` and is gitignored; this publication-grained set supersedes it.

## `id_field`: `doi`

Chosen after checking every candidate:
- **`doi`** — 259/260 filled, 253 distinct; the natural per-publication key, and all source DOIs
  resolve in the index.
- **`pmid`** — rejected: 12 empty (`PMID:`) plus duplicates.
- **`rowId`** — rejected: the index's internal `rowId` does **not** correspond to the source
  table's `ROW_ID` (verified — they map to different DOIs), so it cannot bridge source-derived
  relevant sets back to the index.

**DOI string inconsistency:** the source stores some DOIs bare (`10.xxxx/…`) and some prefixed
(`https://doi.org/10.xxxx`). `relevant` lists use the **exact stored string** so hits resolve
verbatim. A handful of rows carry malformed/duplicated DOIs (`720`, `eabo5442`, `S1534-…`,
`3883`, `102198`); heads avoid these in favor of clean siblings.

## Domain themes covered

- **Tumor types:** plexiform NF, MPNST, cutaneous NF, schwannoma, optic pathway glioma,
  low-grade glioma, meningioma, atypical neurofibroma / ANNUBP; disease focus **NF2**.
- **Therapies / pathways:** selumetinib, MEK inhibitor, mTOR/PI3K, nonsense-readthrough /
  exon-skipping / antisense gene therapy, Ras/MAPK, TKI / imatinib.
- **Model systems:** mouse, porcine/minipig, iPSC, Schwann-cell biology.
- **-omics / assays:** single-cell RNA-seq, whole-exome sequencing, proteomics, high-throughput
  drug screening.
- **Clinical phenotypes / outcomes:** pain, cognition/learning, quality-of-life PROs, natural
  history, MRI/imaging.

## Notable judgment calls (false friends excluded)

- **`cognition-learning`** excludes "Machine Learning of Allosteric Effects" and "Machine
  learning in rare disease" (computational methods, not cognition).
- **`ras-mapk-signaling`** excludes a RASopathy-autism symptom-profile paper and a resting-state
  fMRI paper (match "Ras" only via "RASopathies"; behavioral, not pathway biology).
- **`mouse-model`** excludes an eLife dLight1 dopamine-imaging outlier.
- **`porcine-minipig-model`** excludes rows matching only the `%pig%` substring.
- **`nf2`** excludes the 2026 crossMoDA imaging-challenge dataset row.

## Coverage gaps — the schema limit

**This table has no `abstract` column** — the only substantial free text is `title`. Several
-omics/model intents that are common in the NF literature have **zero** groundable rows by title
alone (e.g. zebrafish, CRISPR screens, PDX), so no case was created for them rather than emit an
empty or forced head. `fields.yaml` reflects this by weighting `title` heavily. Coverage is
therefore honest but title-bounded; intents living only in abstracts are not represented.
